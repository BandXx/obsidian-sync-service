# Obsidian 云端同步 · 用户入门手册

> 适用版本：插件 Self-hosted LiveSync 1.0.46 / Obsidian ≥ 1.7.2
> 服务端：`https://YOUR_DOMAIN/couch`（VPS，CouchDB 3.4）
> 手册更新：2026-11-07

---

## 一、这套东西是什么

你的笔记**存两处**：本地一份完整副本，服务器一份加密主存储。保存后几秒内自动上传，换设备打开就能看到最新内容。断网照常写，联网后自动补传。

- **加密在客户端做**：出口前就切块加密（AES-256，口令只有我们自己知道）。服务器上只有密文块，看不到正文。
- **服务器能看到什么**：文档数量、每块大小、修改时间。看不到内容，也看不到文件名（路径混淆已开）。

## 二、第一次装（10 分钟）

### 装备清单

| 事项 | 要求 |
|---|---|
| Obsidian | 1.7.2 或更高 |
| 网络 | 能访问 `YOUR_DOMAIN` |
| 参数 | 5 个值，见下方"填什么" |
| 手机 | 可以装（插件非桌面限定），iOS/Android 都行 |

### 装插件

1. 打开 Obsidian → `设置` → `第三方插件` → 关闭「安全模式」
2. `浏览` → 搜 **Self-hosted LiveSync** → 安装 → 启用
   （作者 vorotamoroz。国内网络打不开市场的话，从 GitHub release 下 `main.js`、`manifest.json`、`styles.css` 三个文件，丢进 `vault/.obsidian/plugins/obsidian-livesync/`）
3. 启用后左侧栏会出现插件设置入口

### 填什么

在 LiveSync 设置里找到「远程配置 / Remote Configuration」，按表填：

| 字段 | 值 |
|---|---|
| URI | `https://YOUR_DOMAIN/couch` |
| Username | `alice`（你自己的账号名，见下方说明） |
| Password | 你的密码 |
| Database name | `obsidiannotes` |
| End-to-end encryption passphrase | `‹E2E-PASSPHRASE-见库外凭据›` |

**URI 结尾不能带库名**，也不能只写 `https://YOUR_DOMAIN`（那样会 404 —— CouchDB 挂在 `/couch/` 子路径下）。

### 打开同步

同一页打开这四项，缺一不可：

- `Enable LiveSync`（总开关）
- `Sync on Save`（保存即同步）
- `Sync on Start`（启动即拉取）
- `Periodic Replication`（定时兜底，周期 300 秒）

然后命令面板（`Cmd/Ctrl + P`）→ 输入 `LiveSync` → 选 **Sync now**，首次会把整个库上传或拉下来。

### 验证装好了

最可靠的验证是看日志：命令面板 → `LiveSync: Show log`，看到 `SYNC` 相关记录、没有红色报错就是通的。

再稳一点：在 A 设备新建一篇笔记，等十几秒，在 B 设备 **Sync now**，能不能看到这篇。看到就是真的通了。

## 三、日常怎么用

就一件事：**正常写，正常保存**。剩下的自动。

| 场景 | 会发生什么 |
|---|---|
| 保存笔记 | 几秒内上传 |
| 断网写字 | 存本地，联网后自动补传，不丢 |
| 换设备打开 | 启动时拉取，看到的是最新 |
| 手机上改 | 和 Mac 一样，双向同步 |
| 两人改同一篇 | 都会保留 —— 后同步的一方会生成 `文件名.conflict.md` 副本，内容不丢，需要人工合并 |

**别做的事**：不要在同一个 vault 上再开第二套同步方案（iCloud、Dropbox、Obsidian Sync、Git 自动推送）。两套写同一批文件会互相覆盖、造出大量冲突副本。插件启动时自己也会警告这一点。

## 四、权限：两种账号

服务器上有两种身份，由管理员在服务器侧分配，客户端填的账号决定你能做什么。

| 角色 | 能读 | 能写 | 适合谁 |
|---|---|---|---|
| `editor` | ✅ | ✅ | 一起写的人 |
| `reader` | ✅ | ❌ 服务端直接 403 | 只看不改的人 |

只读账号能正常拉取、正常阅读，但任何写入都会被服务器拒绝。给只读成员用的设备，建议只用来**看**，不要在那边编辑（编辑会不断上传失败、日志刷 403，虽然不影响本地内容）。

## 五、故障速查

先看插件的日志：命令面板 → `LiveSync: Show log`（或左侧栏「Self-hosted LiveSync 日志」）。日志里最后几行通常直接写着原因。

| 现象 | 原因 | 处理 |
|---|---|---|
| `远程数据库较新或已损坏,请确保已安装最新版本` + 一个字节都不上传 | 云端库里存在**非本插件创建的文档**，插件判定"这库是别的程序建的"，拒绝初始化 | 见第八节，这是部署期踩过的坑，一般用户碰不到 |
| `401 Unauthorized` | 账号或密码错 | 核对，注意别把 `livesync`（管理员）当成自己的账号 |
| `403 read-only account` | 用的是 `reader` 账号去写 | 正常，只读账号就该这样 |
| 连不上、一直转 | 网络或证书 | 浏览器打开 `https://YOUR_DOMAIN/couch`，应弹登录框；打不开就是网络问题 |
| 能同步但很慢 | 文件大 / 服务器内存紧 | 服务器只有 1.6G 内存，多人同时传大附件会慢，正常 |
| 两台设备内容对不上 | 一台还没跑完同步 | 在缺内容那台手动 **Sync now** |
| 出现 `.conflict` 文件 | 两人同时改了同一篇 | 人工合并，删掉冲突副本 |

## 六、三条铁律

1. **E2E 口令绝不能改。** 改了等于换了一整套加密体系，旧数据全部读不出来。要改必须所有设备停同步、重建库。存进密码管理器。
2. **一个 vault 只跑一套同步。** 见第三节末尾。
3. **改完设置要重启 Obsidian 验证一次。** 插件设置热加载偶尔不彻底，重启后看状态栏箭头是否正常。

## 七、服务器在哪、找谁

| 项 | 值 |
|---|---|
| 地址 | VPS `YOUR_SERVER_IP` |
| 域名 | `YOUR_DOMAIN` |
| 数据库 | CouchDB 3.4，容器名 `couchdb-livesync`，库 `obsidiannotes` |
| 数据落盘 | `/opt/couchdb/data` |
| 证书 | Let's Encrypt，自动续期（2027-02-05 到期前会续） |

服务器上的运维命令、备份方法、加账号的方法，都在 `Obsidian-云端协作-部署记录.md` 里，那是给管理员看的。

## 八、给管理员：部署期踩过的那个坑

留档备查，普通用户不用管。

**现象**：插件能连、能认证、能读 `_changes`，但一个文档都不写。日志只有：

```
OneShot同步开始...(pullOnly)
远程数据库较新或已损坏,请确保已安装最新版本的self-hosted-livesync
```

**根因**：LiveSync 的 `checkRemoteVersion()` 在远程缺版本文档 `obsydian_livesync_version` 时，会读 `db.info().doc_count`，**只要大于 0 就判定"这库属于别的程序"并拒绝初始化**。当时为了做只读权限，提前往库里放了 `_design/permissions`，`doc_count = 1`，初始化永远走不通。

**修复顺序**（顺序不能换）：

1. 备份并删除 `_design/permissions` → `doc_count` 归 0
2. 客户端跑一次同步 → 生成 `obsydian_livesync_version` 和文件块
3. 把 `_design/permissions` 放回去

**推论**：以后新建库，**先让 LiveSync 初始化，再往里加任何自己的文档**。反过来做就会重演。
