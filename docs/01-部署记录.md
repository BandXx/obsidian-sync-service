## 一、最终架构

```
                 ┌──────────────────────────────────────────┐
   你的 Mac ────┐│  nginx 443 (YOUR_DOMAIN, Let's Encrypt)│
   手机/iPad ───┼┼─ /couch/  ──► 127.0.0.1:5984  CouchDB      │──► /opt/couchdb/data (主存储)
   团队成员 ────┘│  /ws-mux/ ──► 127.0.0.1:3210 Live Share中继 │
                 └──────────────────────────────────────────┘
```

两条独立通道，互补：

| 通道 | 用途 | 数据在哪 | 权限 |
|---|---|---|---|
| **LiveSync + CouchDB**（主） | 日常多设备同步、手机端、事后分享 | 服务器 CouchDB，是**主存储** | CouchDB 账号 + `_security` + 只读角色 |
| **Live Share**（辅） | 同一分钟、同一份文件的实时共编 | 服务端纯中继，不存内容 | 只有邀请链接，无账号体系 |

平时用 LiveSync；需要「像 Google Docs 一样同时改同一段」时，临时开 Live Share。

### 首次同步为什么卡住过（真实根因，务必记住）

现象：插件能连上、能认证、能读 `_changes`，但一个文档都不写；日志里只有

```
OneShot同步开始...(pullOnly)
远程数据库较新或已损坏,请确保已安装最新版本的self-hosted-livesync
无法连接到服务器
```

根因在 LiveSync 的 `checkRemoteVersion()`：远程缺少版本文档 `obsydian_livesync_version` 时，它去读 `db.info().doc_count`，**只要 `doc_count > 0` 就判定「这个库是别的程序建的」并拒绝初始化**。我们为了做只读权限，提前在库里放了 `_design/permissions`，于是 `doc_count = 1`，初始化永远走不通。

修复顺序（关键：先清空、再让插件初始化、最后把权限文档放回去）：

```bash
B=https://YOUR_DOMAIN/couch
# 1. 备份并删掉设计文档（需要管理员）
curl -s -u livesync:$COUCH_PASS "$B/obsidiannotes/_design/permissions" > /root/permissions.json
REV=$(python3 -c 'import json;print(json.load(open("/root/permissions.json"))["_rev"])')
curl -s -X DELETE -u livesync:$COUCH_PASS "$B/obsidiannotes/_design/permissions?rev=$REV"
# doc_count 必须变成 0

# 2. 在 Obsidian 里跑一次同步（命令面板 → LiveSync: Sync now / Replicate now）
#    成功后库里会出现 obsydian_livesync_version 与 f:/h: 文档

# 3. 把权限文档放回（此时版本文档已存在，不会再触发那条判断）
```

**以后加新库同理**：先让 LiveSync 初始化完，再往库里加任何自己的文档/设计文档。反过来做就会重演这个故障。

## 四、给别人开权限

### 加一个能读写的成员
在服务器执行：

```bash
source /opt/couchdb/.env
P='给对方的密码'
H=$(printf '%s:%s' "$COUCH_USER" "$COUCH_PASS" | base64 -w0)
curl -s -X PUT -H "Authorization: Basic $H" -H 'Content-Type: application/json' \
  "http://127.0.0.1:5984/_users/org.couchdb.user:对方用户名" \
  -d "{\"name\":\"对方用户名\",\"password\":\"$P\",\"roles\":[\"sync-user\",\"editor\"],\"type\":\"user\"}"
```

### 加一个只读成员
同上，`roles` 改成 `["sync-user","reader"]`。对方能同步下来看，写不进去（服务端 403）。

### 收回
```bash
H=$(printf '%s:%s' "$COUCH_USER" "$COUCH_PASS" | base64 -w0)
curl -s -X DELETE -H "Authorization: Basic $H" \
  "http://127.0.0.1:5984/_users/org.couchdb.user:对方用户名"
```
对方下次同步就会 401，立刻断开。

## 六、和另外两个插件的冲突处理（重要）

vault 里现在同时装着三个会动文件的插件，双写会互相覆盖：

| 插件 | 状态 | 说明 |
|---|---|---|
| `obsidian-livesync` | **已启用** | 主同步，自动 |
| `obsidian-git` | **已停用** | 停用前它陷入死循环：`fatal: ambiguous argument ':未命名 1.base'`（文件名带空格+CJK 触发 obsidian-git 的 `:path` 语法 bug），每几秒重试一次，`exitCode 128`。而且它 push 的裸仓库和 CouchDB 在同一台服务器同一块盘上，算不上备份 |
| `live-share` | **已停用** | 停用前它每次启动都自动恢复 hosting（状态栏长期显示 `Live Share: hosting`），和 LiveSync 双写同一个 vault |

两个插件只是停用、没删，随时可以在「第三方插件」里重新打开。真正需要「同一段文字同时改」时再开 `live-share` 并 `Start session`，用完关掉。

LiveSync 插件自己在设置里也提示「请确保没有其他同步方案同时运行」。

## 七、已知限制

1. CouchDB 挂在 `/couch/` 子路径，不是根路径。这是官方推荐做法，但意味着**不能**把 URI 写成 `https://YOUR_DOMAIN`（会 404）。
2. 服务器 1.6G 内存，多人 + 大文件同时同步时要看 `free -m`。CouchDB 的 `mem_limit` 是 512m 上限。
3. 手机端必须走 HTTPS 有效证书，证书 2027-02-05 到期，`certbot.timer` 自动续期已开。
4. E2E 加密是客户端做的：服务器上的文档块是密文，但**文档数量、大小、修改时间**这类元数据服务器能看到。
5. 停用 `obsidian-git` 后，vault 不再有 Git 历史版本。要历史请用 CouchDB 侧备份（第五节）或重新启用 Git 但改成手动 commit。
6. 早期给的那套 `Live Share + Git` 方案里，Live Share 只能实时共编、Git 只是备份，都不是「云端主存储 + 可管理权限」。本方案才是。
